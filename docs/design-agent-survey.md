# agent-survey：设计（2026-10-21）

> 一句话：**越问越短的表单。** 调用方交给它一份说明和一些已知信息，它派一个 agent 去问受访者，问完交回一份**原样的记录**。记录拿去干什么，不归它管。

这份文档是改造的依据。仓库、代码与部署标识（Worker / D1 / R2）都叫 agent-survey；改名会丢进行中的访谈、让已发链接失效，所以名称现在固定下来。

## 1. 它是什么，不是什么

- 一个**完全独立**的工具：不知道任何调用它的系统。引擎代码里没有任何领域词，领域知识只在 `templates/` 里。这一条是测试（`src/shared/independence.test.ts`），不是自觉。
- 它不是 Google Form：题不是固定的。agent 每轮现出题，已知的不再问，选项尽量替受访者猜好，没想好的留到最后补问。
- 它不对结果做任何处理：没有“交付物”，没有“整理稿”，没有结构化 schema。给出去的是一份尽量原始的记录，怎么理解归拿它的人。

## 2. 词汇

| 词 | 含义 |
|---|---|
| 受访者 | 回答问题的人 |
| 提问方 | 发起访谈的人 / 系统 |
| template | 可复用的访谈模板（旧称 profile） |
| 一次访谈 | 用某个 template + 这次的背景发起，有自己的链接 |
| 已知信息 | 提问方预置的文件、网址、文字。分两种出处：`respondent`（受访者提供的，算他说过的话，可作选项依据）和 `inquirer`（提问方做的调研，只能当线索） |
| 记录 | 访谈结束后交回的原始资料（见 §5） |

## 3. template（可复用）

| 字段 | 必填 | 说明 |
|---|---|---|
| `name`、`version` | 是 | 创建访谈时整份快照，之后改模板不影响进行中的访谈 |
| `goal` | 是 | 目标描述：这场访谈要弄清什么（给 agent 看） |
| `criteria` | 否 | 验收条款：每条一句能答“是 / 否”的陈述。有就在结束前验证 |
| `respondent` | 否 | 受访者说明：外行还是专家，决定减负门的松紧 |
| `intro` | 否 | 开场说明：给受访者看的，谁在问、为什么问、大约多久 |
| `pace` | 否 | `{ maxRounds?, perRound? }`，**默认不设限** |
| `capabilities` | 否 | `{ web?, search?, uploads? }`，**默认全开** |
| `language` | 否 | 默认中文 |

没有“题型黑名单”：不想收文件，写进 `goal`；想强制，用 `capabilities.uploads = false`（题型词表是封闭的，这是一道零成本的门）。

## 4. 一次访谈（创建时传）

`template`（名字，默认 `blank`）、`brief`（这次的背景）、`goal` 补充（`append`）或整段覆盖（`goal`）、已知信息（文件 / 网址，各带出处）、受访者称呼、`model`、`notify`（完成回调地址）。

## 5. 记录（结束时封口，不可变）

`GET /admin/interviews/<code>/result` 返回：

1. **对话**：每一轮的题（题号、题型、给了哪些选项、选项是猜的还是出自受访者的话、为什么问）、受访者的回答（选了什么、写了什么、跳过或稍后再答）、他在每轮底部额外写的话。
2. **材料**：受访者补充的和提问方预置的文件与网址，各有存放键、原文件名、类型、大小、sha256、出处、哪一轮给的。agent 转出来的文字是派生物，单独存并标明转换成没成功。agent 读过的网页也存下来。
3. **agent 的解读**：它看过材料之后形成的结论，**标明是解读，不是受访者的话**。每条带依据（题号 / 文件 / 网页 + 一句原话），原话在引擎里机械核对确实出现在那一处。
4. **没答的**：稍后再答、始终没答。
5. **验证**：每条验收条款的结论和依据；拦了几次；结束时还有哪几条不满足。
6. **元数据**：目标与背景的原文快照、template 名和版本、模型、谁结束的、时间、整份记录的摘要（digest）。

没有 CONTEXT.md，没有 facts.json，没有 model.json。需要人读的版本，由记录机械渲染。

## 6. 目标验证

- 验证 = 独立的判断者对**每一条**验收条款回答一次“是 / 否”，**必须引用记录里的一句原话作为依据**。依据在引擎里核对存在，找不到就当不成立。
- 单条单问：合成一个“全满足”的大问题不可靠（`docs/clef-bool-2026-10-18.md`）。
- 没有验收条款 = 不验证：没有待补答的题，agent 想结束就可以结束。
- 不死锁：最多拦 `MAX_FINISH_BLOCKS` 次，之后放行，把没满足的条款写进记录。判断者不可用 = 放行并计数。回头补答那一轮是最后一轮，不再拦。

## 7. 完成回调（第一版只是个样子）

创建时可填 `notify`。访谈结束（`phase = done`）时 POST 一次：`{ id, phase, resultUrl }`。**不重试、不签名、不保证送达**；调用方仍可用 `wait` 轮询。出现“回调丢了导致下游没动”的那一次，再补重试和签名。

## 8. 明确不做

- **保留与删除策略**：记录会一直留着，除非提问方显式 `DELETE` 一个访谈（已有）。受访者是陌生人、或记录里可能出现敏感信息时，要重新考虑。
- 验证回调（调用方自己的领域规则）：调用方拿到记录后自己校验，不过就重开（后续做 `reopen`）。
- 结构化 schema / 交付物：见 §1。

## 9. 保留的不变量

稍后再答一个都不丢（`machine.ts`）；受访者的输入一律不可信（富文本白名单、文件和网页当数据）；每轮题数和作文题的减负门；`mode: confirm` 的选项依据必须逐字出自受访者的话；上传不半收；预置资料的出处区分；流程判断只在状态机里。

## 10. 改动顺序

1. template 取代 profile（含 D1 列改名）。
2. 去掉交付物（`/CONTEXT.md`、`/facts.json`、`/model.json`、对应 schema 与 gate、`propose_model`、`record_facts`、`--from` 交接）。
3. 验收条款 + 逐条验证。
4. 记录：解读（`note_finding`）、agent 读过的网页入档、`result` 重做。
5. 回调。
6. 节奏 / 能力 / 受访者说明 / 开场说明 / 语言接进提示词和工具。
7. 去领域词 + 独立性测试；`client` / `ours` → `respondent` / `inquirer`。
8. 文档、说明书、命令行。
