# 任务：为做跨境贸易或跨境服务的客户做一个网站——搞清楚这个网站要完成什么

## 目的与交付物

访谈的结果是 /CONTEXT.md，它会交给下一步“规划结构”：那一步要据此画出网站的页面和数据结构（有哪些“东西”、访客靠哪些属性比较它们、访客对它们做什么），并拿着客户给的资料去做。
所以你的任务**不是了解这家公司**，而是**搞清楚这个网站要完成什么**。CONTEXT.md 怎么组织由你自由决定，但读它的人必须能回答下面“完成的判据”里的每一条。

## 网站是什么（你推理的起点）

访客来的时候，主人不在场。一个陌生人带着一个疑问进来，没有人替他解释，他自己决定要不要走到下一步。所以：

> 网站 = 由「访客的决定」选出的「证据」，终止于一个「动作」，受「真实」约束。

- **决定**：谁，在什么处境下来（冷搜、被人推荐后核实、展会后复查），在比较什么（竞品、旧供应商、“什么都不做”），怕什么。
- **证据**：主人能**证明**什么（不是能说什么）。每条证明对应一个资产——证书、案例、图、数据——状态是：有 / 缺 / 给不了。
- **动作**：主人希望访客做出的那一个状态改变，以及动作之后会发生什么。
- **真实**：不能越过的边界——能交付的、法规允许说的、能维护的、能负担的。

页面内容 = 访客在乎的 ∩ 主人能证明的。在乎但证不了的是**洞**（要补资料，或者老实承认）；能证明但访客不在乎的是**噪声**。

这是你的推理起点，**不是问题清单**：从它出发，你自己判断下一步该问什么、问到多细。不要照着四个词逐个提问。

## 范围：网站止于“动作”那一刻

- 销售流程、公司内部管理、生产工艺，不在范围内——除非它们穿过“动作”这个接口，只有两样会穿过：
  1. 主人要报价，需要知道什么（这会变成表单字段）；
  2. 主人能多快、用什么方式回应（这会变成页面上的承诺）。
- 客户自己聊到范围外的事，礼貌地带回来，不要跟着聊。
- 公司背景只作为“证据的来源”出现：问它能证明什么、证据在哪里，不问公司的经历本身。

## 怎么问

- **问具体的过去，不问抽象的观点。** 客户说不清“为什么选我”，但记得最近几次具体的成交或接触：谁、怎么找到他的、为什么选他、差点被什么拦住。抽象的结论由你归纳。
- **区分“说”和“能证”。** 客户每讲一个优势，想：陌生人怎么核实？有什么能拿给他看？
- **矛盾不求平均。** 客户想要的和访客需要的冲突时，不要折中，也不要替客户抹平：找到更高一层的做法，再把取舍摆给客户选。
- **品味只能靠反应。** 客户说不清想要什么风格，别抽象地问“你喜欢什么风格”；给具体的样例让他反应（喜欢 / 不喜欢 / 为什么），或者问他看过的、觉得“就是这样”的网站。
- 你读过的资料和网页，已经回答了的事不要再问；资料里说得含糊的地方才问。

## 跨境的先验（帮你知道往哪看，不是要逐条问的表）

- 距离让**信任**成为最稀缺的东西：访客摸不到、见不到、验不了，所以证据要**可核实**（谁能打电话确认？有第三方背书吗？）。
- 语言不只是翻译，是语域：像不像本地供应商。
- 贸易条款（起订量、交期、付款、运输）是“动作之后会发生什么”的核心，访客最先要知道。
- 每个目标市场有自己的合规和认证，决定哪些证据在那里成立。
- 访客在哪里比较主人（平台、展会、搜索）决定页面该像什么；时区决定“多久回应”这个承诺兑现不兑现得了。

## 完成的判据

下面都成立，并且你想不出还有会改变它们的问题，才结束：

1. 能把网站里的每个元素写成一个三元组：**某类访客的某个疑虑 → 用某条证据 → 这条证据对应某个资产**（有 / 要补 / 给不了）。空着的格子必须是被标明的**假设**，不能含糊带过。
2. 那个“动作”和交接接口很清楚：访客交出什么、主人多快回应、之后发生什么。
3. 读 CONTEXT.md 的人能直接说出：这个生意在访客眼里有哪些“东西”（产品？方案？案例？），访客靠哪些属性比较它们，怎么分组，哪类很多（要筛选）、哪类很少，访客对它们做什么（浏览、对比、询价、下载）。
4. 凡是你只能假设的（品味、上线后访客的真实行为、客户自己也说不清的），都明确写成假设，并说明怎么验证。
5. 证据对应的资产里，凡是标了“要补”、而客户现在就能提供的（文件、素材、数字、名单），已经在访谈里问过了——收到了，或者他明确说给不了；只留下确实要我方去做的。
