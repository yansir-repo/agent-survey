# clef 做“单题布尔判断”：可用（2026-10-18）

上一次（docs/model-comparison-2026-10-17.md 末尾）放弃的是**需要读懂语境**的判断（范围、重复、意外检测）。
这次换了问法：输入只有**一道题的标题和方式**，问一个闭合的两选一——结果完全不同。

数据：线上 dogfood 访谈 `yan-dogfood` 的 38 道题；标签是我读过标题后手标的（self-authored，只能当上限）。
脚本和实验端点（`scripts/clef-bool-exp.mjs`、`/admin/clef-ask`）实验完成后已删除，要复现从 git 历史（提交 b84c336）里取。

| 条件 | 发法 | AUC | 最佳阈值下准确率 |
|---|---|---|---|
| 该拆吗（同时问几件事）n=38 | S 每条件一请求 | 0.99 | 95% |
| | P 每题一请求、两条件并列 | 0.97 | 95% |
| | B 全部合一个请求 | 0.96 | 87% |
| 能改选择题吗 n=24（只取我有把握的） | S | 0.97 | 83% |
| | P | 0.97 | 96% |
| | B | 0.97 | 92% |
| 复合问题“只问一件事且能选” | C | 0.87 | 79% |

- **发法**：S/P 一致性好（平均绝对差 0.06–0.07），B 明显漂（0.13–0.16）；耗时 S 6.1s（76 个请求并发 4）、P 4.6s（38 个）、B 2.6s（2 个）。
  → 采用 **P**：每题一个请求，两条件并列。**不要把条件合成一个“全满足”的复合问题**（AUC 0.87，比拆开差）。
- **“能选”的概率整体偏低**（能选 0.23 / 得写 0.03），0.5 的默认阈值会错 58%：阈值必须按分布定（取 0.15）。
- 局限：标签是自己标的，n 小，阈值用同一批数据选的（过拟合风险）。接入后以线上 `stat.clefRefused`、`stat.clefDown` 和人工抽查为准。
- **只用于文字类题（text / long / rich）**：线上第一轮对照里 clef 退回了 6 次，其中 5 次是选择题（标题带“（可多选）”“哪几样”），人工看 4 次是误报。阈值是在文字类题上标的，不外推到选择题；选择题一题多问由“一题一个问号”的规则和选项数上限兜住。
- 接入处：`src/worker/interview.ts` 的 `clefProblems`（askRound 里，规则校验之后）。clef 不可用 = 放行并计数；连续被退回 2 次后本轮不再问它。
